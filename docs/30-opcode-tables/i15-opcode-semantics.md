# I.5 各 opcode 在做什麼

[opcode 表與版本陷阱](version-traps.md)列出了 1978 年 I.5 的助記符，但只有名字。
這一篇補語意，並且拿它跟 IV.0 對照。

> 延伸閱讀：[opcode 表與版本陷阱](version-traps.md)｜
> [程序呼叫怎麼進行](../10-p-machine/procedure-call.md)｜
> [segment 為什麼這樣切](../10-p-machine/segment-and-environment.md)

結論先講：語意不必推測——**`mainop.mac` 與 `procop.mac` 每一個處理常式都帶作者自己寫的
註解**，80 個助記符一個不漏。真正有價值的是拿兩版並排之後看見的方向：
**I.5 → IV.0 之間，能在編譯期算的東西被搬到了編譯期**，而這一個決定連帶改掉了
呼叫指令的分類、Mark Stack 的內容，以及一批專用指令的存廢。

## 語意是從哪來的

I.5 的原始碼是 PDP-11 MACRO-11 組語，每個 opcode 的處理常式長這樣：

```
 ADI:    ; ADD INTEGER
         ADD     (SP)+,@SP
         MORE
```

標籤是助記符、分號後面是作者寫的語意。抽取方式是掃「標籤加註解」這個樣式，
再與 `XFRTBL` 解出的 opcode 對應接起來。80 個助記符全部找得到註解，沒有缺口。

下表的「語意」欄就是那些註解的中譯，不是我的解讀。需要另外讀碼才說得清楚的，
在後面單獨談。

## 短形式（0–127、216–255）

| opcode 範圍 | 指令 | 運算元 |
|---|---|---|
| 0–127 | `SLDC` | opcode 值本身就是常數 |
| 216–231 | `SLDL1`–`SLDL16` | 區域變數編號 |
| 232–247 | `SLDO1`–`SLDO16` | 全域變數編號 |
| 248–255 | `SIND0`–`SIND7` | 間接載入的偏移 |

`SIND0` 在 `mainop.mac` 裡有一段值得看的註解——`.BLKW 2 ; FUNNY BUSINESS FOR EXTRA FAST IND 0`。
偏移 0 的間接載入不必加偏移，所以它的常式短兩條指令，用 `.BLKW` 把後面對齊回來。
**連短形式內部都在為最常見的那一格再省一次。**

## 演化一：層數從執行期搬到編譯期

這是兩版之間最有結果的一個改動。

I.5 的 `CIP`（呼叫中間層程序）**只有一個運算元**，就是程序號——沒有帶「要回溯幾層」。
那它怎麼找到被呼叫者的靜態父層？答案是執行期搜尋：

```
ENDCIP: MOVB  1(R1),BK       ; 從被呼叫者的 JTAB 取它的 lex level
        BLE   ENDCBP         ; ≤ 0 就當成 base 呼叫
        MOV   MP,R0
1$:     MOV   MSJTAB(R0),R1  ; 取這個框存的 JTAB
        CMPB  1(R1),BK       ; 比 lex level
        BLT   2$             ; 比被呼叫者低 → 找到父層
        MOV   MSDYN(R0),R0   ; 否則沿動態鏈往下一個框
        BR    1$
```

**沿著動態鏈一格一格走，比對 lex level，直到找到層級較低的框。**
成本與呼叫深度成正比，而且每次呼叫都要付。

IV.0 的 `CPI DB, UB` 把層數編進指令，執行期只要沿靜態鏈走 `DB` 步；
更進一步，走 0 步、1 步、2 步與「直達 `BASE`」這四種最常見的情形各給一個獨立的 opcode
（`CPL`、`SCPI1`、`SCPI2`、`CPG`），常見情形連走都不用走。
推導見[程序呼叫怎麼進行](../10-p-machine/procedure-call.md)。

這個改動的連鎖效應在下一節。

## 演化二：Mark Stack 從 6 個 word 變成 5 個

I.5 的 MSCW 欄位定義（`macros.mac`，偏移是八進位）：

| I.5 欄位 | 內容 | IV.0 對應 | 變化 |
|---|---|---|---|
| `MSSTAT` | 靜態鏈 | `MSSTAT` | 同 |
| `MSDYN` | 動態鏈 | `MSDYN` | 同 |
| `MSJTAB` | 呼叫者的 **JTAB 指標** | `MSPROC` 呼叫者的**程序編號** | 指標 → 編號 |
| `MSSEG` | 呼叫者的 **segment table 位址** | `MSENV` 呼叫者的 **E_Rec 指標** | 段表 → 環境記錄 |
| `MSIPC` | 呼叫點的**絕對記憶體位址** | `MSIPC` 呼叫點的**段內相對**位移 | 絕對 → 相對 |
| `MSSP` | 離開時要還原的 SP | 無 | 砍掉 |
| `MSBASE` | BASE 暫存器（只在 base MSCW） | 無 | 砍掉 |

三件事值得分開看。

**`MSIPC` 從絕對變相對。** I.5 的註解明寫 `ABSOLUTE MEM ADDR OF NEXT OPCODE IN CALLER`。
I.5 存絕對位址是可行的，因為它沒有 IV.0 那套會**整塊搬動 Codepool** 的記憶體管理。
IV.0 引入之後絕對位址隨時可能失效，於是改成「段內相對位移」加「程序編號」這組
搬移後仍然有效的座標——推導見
[segment 為什麼這樣切](../10-p-machine/segment-and-environment.md)。

**`MSJTAB` 從指標變編號。** 同一條理由（指標會失效）之外還有一層：I.5 之所以要存
JTAB **指標**，是因為上一節的 `CIP` 需要在執行期從框反查 lex level，而 lex level 就存在
JTAB 裡。層數搬到編譯期之後，執行期不再需要查 lex level，這一格就沒有理由存指標了。
**一個決定同時解掉兩個問題。**

**`MSSP` 被砍掉。** IV.0 的 `RPU` 帶一個 `B` 運算元說明要從堆疊削掉幾個 word，
不必在每個框裡存一份 SP。呼叫點通常比返回點多，但這個資訊在返回指令裡只出現一次，
而框是每次呼叫都要建的——**把它從「每次呼叫的空間」搬到「每個程序一次的指令」**。

## 演化三：砍掉能用別的指令組合出來的

I.5 有一批專用 opcode，在 IV.0 消失了：

| I.5 有 | 做什麼 | IV.0 怎麼辦 |
|---|---|---|
| `SQI` / `SQR` | 整數／實數平方 | 用 `DUP1` + `MPI`（IV.0 有 `DUP1`，I.5 沒有） |
| `FLO` | 把**次頂**轉成實數 | 用 `SWAP` + `FLT`（IV.0 有 `SWAP`，I.5 沒有） |
| `GRTI` / `LESI` | 整數嚴格大於／小於 | 只留 `LEQI` / `GEQI`，另一邊交換運算元 |
| `S1P` / `S2P` | 字串與 packed array 互轉 | 併進 `ASTR` 那組字串指令 |
| `BYT` | word 位址轉 byte 位址 | byte 指標改用兩個 word 表示，不必轉換 |
| `IXS` | 字串索引加範圍檢查 | 拆成 `CSTR`（檢查）與一般索引 |
| `COMPAR` ×6 | 一個常式，型別由運算元決定 | 攤平成每個型別各自的 opcode |

方向很一致：**把「一個 opcode 做一件很專門的事」換成「兩個通用 opcode 組合」**，
省下來的編碼空間拿去開新的短形式與跨段呼叫。
[版本陷阱](version-traps.md)那篇說短形式從四種變七種，空間就是這樣挪出來的。

`COMPAR` 是其中最有意思的一個。I.5 的作法是二維表：opcode 選比較運算
（`=`、`>`、`≥`、`≤`、`<`、`≠` 六個 opcode），運算元選資料型別，直譯器再查 `CMPTBL`
分派到 real／string／boolean／set／byte／word 各自的常式。
IV.0 把這張二維表攤平——`EQUI`、`EQBYT`、`EQSTR`、`EQPWR`、`EQREAL` 各自一個 opcode。
攤平之後每個組合都是單一位元組、不必再查子表，代價是吃掉更多 opcode 值。

## 錯誤碼在兩版之間沒有變

I.5 的 `macros.mac` 直接定義了執行期錯誤碼（八進位）：

| 值 | I.5 常數 | 意思 | IV.2.1 對應入口 |
|---|---|---|---|
| 1 | `INVNDX` | 索引或範圍檢查失敗 | `0x02ec` |
| 2 | `NOPROC` | 程序不存在 | `0x02f0` |
| 5 | `INTOVR` | 整數溢位 | `0x02f4` |
| 6 | `DIVZER` | 除以零 | `0x02f8` |
| 8 | `UBREAK` | 使用者中斷 | `0x02fc` |
| 10 | `UIOERR` | 使用者 I/O 錯誤 | `0x0300` |
| 11 | `NOTIMP` | 指令未實作 | `0x0304` |
| 12 | `FPIERR` | 浮點錯誤 | `0x0308` |
| 13 | `S2LONG` | 字串太長 | `0x030c` |

右欄是 1985 年 IV.2.1 直譯器裡那一串 `moveq #n,d0` 的位址——
[逐條驗證](iv21-routine-audit.md)是從觸發它們的指令反推語意的，這裡是 1978 年的
常數定義，兩邊逐項對上。**錯誤碼是跨版本穩定的那一類東西**，可以列進
[版本陷阱](version-traps.md)的起手假設。

（IV.2.1 還有一個 `0x0310` 用錯誤碼 16，由 `BPT` 觸發；I.5 的表最大到 15（`BRKPNT`），
這一格對不上，未查證。）

## 同一版有兩套助記符

`mainop.mac` 的標籤名與官方反組譯器 `CODESTAT` 用的名字不完全一樣：

| 直譯器標籤 | `CODESTAT` | IV.0 |
|---|---|---|
| `AND` | `LAND` | `LAND` |
| `IOR` | `LOR` | `LOR` |
| `NOT` | `LNOT` | `BNOT` |
| `MOD` | `MODI` | `MODI` |
| `GRTI` | `GTRI` | — |

本 repo 的表用的是**直譯器標籤**，因為那是 dispatch 表直接對應的名字。
但要注意 `CODESTAT` 那套更接近後來的 IV.0——查資料時兩套都可能遇到。

還有一個更會咬人的：**`CSP` 在兩版都存在，意思完全不同**。
I.5 的 `CSP`（158）是 Call Standard Procedure，呼叫直譯器內建的標準程序；
IV.0 的 `CSP`（172）是 Copy String Parameter。同名、不同號、不同義。

## 邊界

- 語意欄是作者註解的中譯。註解本身可能不精確（`XIT` 寫「離開系統」，
  但它實際的角色是程序碼的結束標記，見[版本陷阱](version-traps.md)）。
  需要更準確的地方要讀常式本體。
- 這份 I.5 是 **PDP-11 版**。同版本移植到 8080／Z80 的直譯器是否有相同的
  opcode 分配與 MSCW 版面，沒有查證。
- 「IV.0 怎麼辦」那一欄有幾項（`SQI` 用 `DUP1`+`MPI`、`FLO` 用 `SWAP`+`FLT`）是推論：
  IV.0 確實有 `DUP1` 與 `SWAP` 而沒有 `SQI`／`FLO`，但編譯器實際產生什麼碼沒有驗過。
