# p-machine 是什麼：為了可攜性而發明的假電腦

1977 年，UCSD 要讓 Pascal 跑在校園裡各式各樣的機器上。
直接為每台機器寫一個編譯器，成本隨機器數量線性增加，而且每加一台就要重寫程式碼產生器。

p-machine 是對這個問題的回答：**先定義一台不存在的電腦，編譯器只產生它的指令；
每種真實機器只要寫一份直譯器**。成本從「機器數 × 語言數」降成「機器數 + 語言數」。

> 延伸閱讀：[指令編碼](../20-pcode-encoding/instruction-encoding.md)

## 為什麼是堆疊機

p-machine 沒有通用暫存器，所有運算在堆疊上做。`ADI`（整數相加）不帶運算元，
它就是「彈出兩個、相加、推回去」。

這個選擇跟可攜性直接相關。若虛擬機有暫存器，直譯器就得把它們映射到真實 CPU 的暫存器——
但 6502 只有三個 8 位元暫存器，PDP-11 有八個 16 位元的。任何固定的暫存器數目，
在某些目標機上都是錯的。

堆疊機沒有這個問題：堆疊住在記憶體裡，每台機器都有記憶體。
代價是指令變多（每個中間值都要進出堆疊），但**指令變短**——
不帶運算元的指令只要一個位元組。對一個以密度為目標的設計，這個交易是划算的。

## 執行時的三個區域

| 區域 | 內容 | 誰維護 |
|---|---|---|
| 程式碼 | p-code 的位元組，按 segment 組織 | 載入時從磁碟讀進來 |
| 堆疊 | 運算的中間值、程序的活動記錄（局部變數、回傳位址） | 每個指令自己 |
| 全域區 | 整個 segment 共用的變數 | 程式生命週期 |

變數存取因此分成兩類，而且**在指令層級就分開**：

- **區域變數**：相對於目前程序的活動記錄（`SLDL`、`LDL`、`STL`）
- **全域變數**：相對於 segment 的全域區基底（`SLDO`、`LDO`、`SRO`、`LAO`）

這個區分在反組譯時很有用：看到全域存取指令，就知道它碰的是一個跨程序共用的狀態，
值得追它的其他存取點；看到區域存取，範圍就限在這支程序裡。

## segment：分離編譯與換入換出

程式按 **segment** 組織，每個 segment 有自己的程序字典與全域區。
這一層存在的理由同樣是記憶體：**一台 48 KB 的機器塞不下整個程式**，
所以只有正在用的 segment 需要在記憶體裡，其餘留在磁碟上，用到才換進來。

所以呼叫指令分兩種——同段呼叫與跨段呼叫。跨段呼叫可能觸發磁碟載入，成本高得多。
反組譯時，跨段呼叫的目標段編號是一條重要線索：它告訴你這支程序屬於哪個功能群。

段的邊界怎麼劃、換入換出要付出哪些簿記代價，見
[segment 為什麼這樣切](segment-and-environment.md)；呼叫指令為什麼分那麼多種，見
[程序呼叫怎麼進行](procedure-call.md)。

## 這對逆向的意義

拿到一份 p-code 想讀懂它，順序是：

1. **先確認它真的是 p-code**，不是原生碼。特徵是磁碟上同時有一個直譯器檔案，
   而程式碼檔案裡看不到目標 CPU 的指令樣式。
2. **解出 opcode 表**（見[從直譯器反推](../40-re-workflow/recover-opcode-table.md)）。
3. **從全域變數的存取點下手**。全域是跨程序的共用狀態，所以一個全域編號會在很多地方出現；
   把它的所有讀寫點列出來，語意通常就浮出來了——寫它的地方少、讀它的地方多，
   而寫它的那幾支程序決定了它是什麼。

第 3 點是實務上最有效的一步。它跟一般的機器碼逆向不同：機器碼裡全域變數是位址，
容易與別的東西混淆；p-code 的全域有明確的編號與專屬指令，**掃描的精確度高得多**。
